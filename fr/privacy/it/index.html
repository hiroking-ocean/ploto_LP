1. Informations sur le produit et le document

Ce document présente les informations techniques relatives à Ploto (ci-après « l'application »), une application de gestion de projet pour Windows, à l'intention des services informatiques. L'URL de cette page, ou une version imprimée ou enregistrée en PDF, peut être utilisée dans le cadre de l'évaluation des applications de votre organisation.

  • Nom du produit : Ploto
  • Systèmes pris en charge : Windows 10 et Windows 11
  • Distribution : Microsoft Store
  • ID produit Microsoft Store : 9N4NJNMT2B77
  • Éditeur affiché dans le Store : hiroki.lab (développeur indépendant)
  • Site officiel : https://ploto-app.com/
  • Contact : hiroki.lab@outlook.com

La décision d'utiliser ou non l'application pour des données professionnelles appartient à votre organisation, au regard de la classification de confidentialité des données, des contrôles d'accès sur les postes et les emplacements de stockage, de vos dispositifs de sauvegarde et de vos règles internes d'utilisation des applications.

2. Distribution, mode d'exécution et privilèges

L'application est une application de bureau développée avec Rust, Tauri et Windows WebView2, distribuée et mise à jour au format MSIX via le Microsoft Store. Elle ne demande pas d'élévation vers les droits d'administrateur en fonctionnement normal.

Le manifeste MSIX déclare runFullTrust afin que l'application puisse fonctionner comme une application de bureau. Cela signifie qu'elle s'exécute avec les mêmes droits que l'utilisateur connecté ; elle n'accorde pas automatiquement de droits d'administrateur. L'application ne crée ni service Windows, ni entrée de démarrage, ni tâche planifiée.

Lorsque le terminal IA est utilisé, l'application lance PowerShell, Git Bash ou WSL comme processus enfant avec les droits de l'utilisateur connecté, et uniquement pendant l'affichage du terminal. Le PowerShell intégré est lancé avec -ExecutionPolicy Bypass pour ce seul processus ; les stratégies d'exécution de l'appareil et de l'utilisateur ne sont pas modifiées (les stratégies d'exécution définies par stratégie de groupe l'emportent sur cette option). Le package contient également l'alias d'exécution ploto-mcp.exe, que les clients d'IA utilisent pour se connecter à Ploto. Il s'agit d'un mode dédié à la connexion, lancé par le client d'IA ; il n'a pas de fenêtre et ne fait que relayer les requêtes vers l'application Ploto.

3. Microsoft Defender et contrôle des applications

Même pour une application certifiée et distribuée via le Microsoft Store, Microsoft Defender ou les réglages de contrôle des applications sur les postes de votre organisation peuvent empêcher l’installation, le démarrage ou l’enregistrement de fichiers. Cette application comporte des exécutables natifs développés avec Rust et Tauri. Les applications de ce type sont plus susceptibles d’être visées par une détection heuristique ou par un blocage fondé sur la diffusion tant qu’une version est récente et dispose de peu d’historique d’exécution (prévalence). La certification du Store ne dispense pas une application des contrôles configurés par votre organisation.

Situations possibles :

  • Faux positifs heuristiques de l’antivirus : les verdicts d’apprentissage automatique fournis par le cloud peuvent placer un nouvel exécutable en quarantaine sous un nom de détection générique tel que Wacatac ou Wacapew. Cela se résout souvent après une mise à jour des renseignements de sécurité.
  • Règles de réduction de la surface d’attaque (ASR) : si la règle « Bloquer l’exécution des fichiers exécutables à moins qu’ils ne répondent à des critères de prévalence, d’âge ou de liste de confiance » est activée, une version récemment publiée peut être bloquée.
  • Accès contrôlé aux dossiers : l’écriture dans des dossiers protégés tels que Documents ou Bureau peut être refusée, ce qui se manifeste par une erreur lors de l’enregistrement d’un fichier .ploto.
  • WDAC et AppLocker : si le signataire ou le package n’est pas autorisé, le package MSIX ne démarre pas du tout.
  • SmartScreen : normalement pas déclenché pour les installations effectuées via le Microsoft Store, mais un avertissement peut apparaître selon la configuration de vos stratégies.

Identité du package (utilisez ces valeurs dans vos règles d'autorisation) :

  • Nom du package (Package/Identity/Name) : hiroki.lab.Ploto
  • Nom de famille du package (PFN) : hiroki.lab.Ploto_va563q7jg714e
  • Signataire déclaré (Package/Identity/Publisher) : CN=AB453F36-8F71-4C99-BB89-582301D0AE38
  • SID du package (pour les règles de pare-feu) : S-1-15-2-1517193112-901780427-1522304721-281083616-2611253276-1887865729-3282081193

Ces valeurs peuvent également être lues sur un poste où l'application est installée, en exécutant Get-AppxPackage dans PowerShell.

PackageFullName et le chemin d'installation changent à chaque version. Pour les règles d'autorisation du contrôle des applications, utilisez le nom du package, le PFN et les informations sur l'éditeur indiqués ci-dessus plutôt qu'un chemin.

Si votre organisation envisage d'autoriser l'application :

  • WDAC et AppLocker : examinez le package installé ou le fichier MSIX et, conformément aux règles de contrôle des applications de votre organisation, créez une règle de package dont le Publisher et le Package name correspondent à cette application. Définissez également la plage de versions autorisée pour les mises à jour conformément à la politique de gestion des changements de votre organisation.
  • Microsoft Defender et ASR : en cas de détection ou de blocage, vérifiez le nom de la détection, le fichier concerné, sa provenance, la signature du package et les enregistrements de la console d'administration, puis suivez les procédures de votre organisation. Si une modification de la protection ou une exception est jugée nécessaire, obtenez l'autorisation de l'administrateur de la sécurité et limitez-la à cette application, au périmètre minimal et à la durée nécessaire.
  • Accès contrôlé aux dossiers : si l'enregistrement est refusé, utilisez d'abord un emplacement de stockage approuvé par votre organisation. S'il est nécessaire d'autoriser l'application, vérifiez que le package provient du Microsoft Store ainsi que sa signature, puis suivez la procédure d'approbation de votre organisation.
  • Signaler un faux positif : si vous concluez qu’une détection est erronée, vous pouvez la signaler via le formulaire de soumission d’échantillons de Microsoft. Si vous transmettez le nom de la détection, la version de Defender et la version de l’application au contact ci-dessous, le fournisseur effectuera également un signalement.

Cette application ne crée ni service Windows, ni entrée de démarrage, ni tâche planifiée (voir la section 2). Une détection est donc probablement un faux positif heuristique, mais la conduite à tenir doit suivre les règles de sécurité opérationnelle de votre organisation.

4. Accès aux fichiers

Techniquement, l'application peut lire et écrire les fichiers auxquels l'utilisateur qui l'exécute a accès. En pratique, elle traite les fichiers que l'utilisateur choisit d'ouvrir, d'enregistrer, d'importer ou d'exporter, les fichiers de configuration et de travail locaux de l'application, ainsi que les fichiers de verrouillage servant à empêcher les modifications simultanées.

Il n'existe aucune fonction analysant l'ensemble des fichiers du poste, surveillant en continu un dossier quelconque, ou téléversant automatiquement des fichiers de projet vers l'extérieur. Les accès en lecture et en écriture aux emplacements de stockage suivent les contrôles d'accès de Windows et de vos serveurs de fichiers.

5. Fichiers et informations enregistrés

Projets : enregistrés sous forme de fichier .ploto à l'emplacement choisi par l'utilisateur. Le format est une base de données SQLite standard contenant les tâches, les noms des personnes affectées, les plannings, les listes de tâches, les notes, les tableaux blancs, les réglages, etc. Les modèles, les sources d'import et les fichiers exportés (Excel par exemple) sont également lus et écrits aux emplacements choisis par l'utilisateur.

Copie de travail : tant qu'un projet est ouvert, une copie de travail du projet entier est créée dans l'espace de données local de l'application géré par Windows. Elle est supprimée à la fermeture normale, et une copie subsistant après un arrêt anormal est supprimée au démarrage suivant lorsque c'est possible.

Fichier de verrouillage : pendant l'édition, un fichier <nom du fichier .ploto>.lock est créé au même emplacement que le projet. Il enregistre le nom d'utilisateur Windows, le nom de l'ordinateur, l'identifiant de processus, l'heure de début et l'heure de mise à jour, et il est supprimé lors d'une fermeture normale. Dans un dossier partagé, il est lisible par tout utilisateur ou administrateur ayant accès à cet emplacement.

Réglages locaux : les préférences d'interface, la clé de licence, l'état d'affichage des messages, les réglages d'éditeur et autres valeurs similaires sont enregistrés dans l'espace de données local de l'application géré par Windows. Les fichiers récemment ouverts sont conservés dans %USERPROFILE%\.ploto\recent-files.json sous forme de 10 chemins au maximum avec leur date de dernier accès. Certains fichiers de réglages auxiliaires sont enregistrés dans %USERPROFILE%\.ploto. Une valeur d'identification aléatoire peut être enregistrée afin de déterminer quelle installation a créé un projet. Cette valeur ne contient ni identifiant matériel du système ni donnée personnelle et n'est pas transmise à l'extérieur.

Intégration IA : l'état du consentement à l'intégration IA, le nombre d'utilisations de l'essai, le code de licence du terminal IA et la date de vérification Store sont enregistrés dans ai-access.v1 dans l'espace de données local de l'application, protégés par Windows DPAPI. À chaque activation de l'intégration IA, le dossier de travail des clients d'IA %USERPROFILE%\.ploto\ai (ainsi que %USERPROFILE%\.ploto\ai-wsl en cas d'utilisation de WSL) est réécrit avec les paramètres de connexion MCP (.mcp.json, opencode.json, .vscode/mcp.json, .cursor/mcp.json, .gemini/settings.json), les instructions destinées à l'IA (AGENTS.md, CLAUDE.md, GEMINI.md, PLOTO.md, references/) et les scripts de connexion (ploto.ps1, ploto.cmd, ploto.sh). Aucun d'eux ne contient d'identifiants. Voir la section 7 pour plus de détails.

6. Communications réseau et domaines à autoriser

Aucune connexion Internet n'est nécessaire pour créer, modifier ou enregistrer des projets, ni pour vérifier une licence achetée. Le WebView intégré à l'application est configuré avec une Content Security Policy qui empêche toute connexion à des sites externes. Les pages externes s'ouvrent dans le navigateur par défaut ou dans le Microsoft Store, uniquement à l'initiative de l'utilisateur.

Pour l'intégration IA, l'application n'accepte que les connexions des clients d'IA du même PC (MCP via un canal nommé et HTTP en boucle locale vers 127.0.0.1), et l'application elle-même n'effectue aucune communication externe liée à l'IA. Voir la section 7 pour le détail des modes de connexion. Les communications de la CLI d'IA avec le service d'IA (par exemple avec les points de terminaison API de chaque service) relèvent des spécifications de la CLI d'IA installée par l'utilisateur et des paramètres réseau de l'organisation.

Si votre organisation restreint le trafic sortant, les principales destinations à considérer sont apps.microsoft.com (fiche produit et avis), buy.stripe.com et checkout.stripe.com (achat en ligne), ploto-v2-license-webhook.vercel.app (finalisation de l'achat et vérification de connexion), docs.google.com (formulaires facultatifs), ploto-app.com (site officiel, manuel et présent document) et hiroking-ocean.github.io (liens de l'application vers le manuel et le présent document). Les domaines annexes de CDN, d'authentification et de polices utilisés par chaque service dépendent de ces prestataires.

Les communications de plateforme liées à Windows Update, au Microsoft Store, au rapport d'erreurs Windows et aux composants analogues suivent les réglages des produits Microsoft appliqués au poste et à votre organisation.

7. Intégration IA (terminal IA et MCP)

Le terminal IA permet aux CLI d'IA que l'utilisateur a installées sur ce PC et auxquelles il s'est connecté avec son propre abonnement (par exemple Claude Code, Codex, Gemini CLI, OpenCode ou GitHub Copilot) de lire et de modifier le projet ouvert dans Ploto. L'application n'intègre ni n'installe automatiquement aucune CLI d'IA et ne gère ni les comptes ni les clés API des services d'IA.

Modes de connexion : l'IA pilote Ploto uniquement par l'une des voies suivantes. Toutes deux sont limitées aux connexions au sein du même PC et inaccessibles depuis les autres appareils du réseau. Aucune API ne donne à l'IA un accès direct aux fichiers de projet ou à la base de données de Ploto.

  • MCP (voie principale) : le client d'IA lance ploto-mcp.exe --mcp-stdio (un alias d'exécution d'application MSIX) comme serveur MCP et communique avec lui par l'entrée et la sortie standard. Ce processus n'a pas de fenêtre et sert uniquement de relais : il transmet les requêtes à l'application Ploto en cours d'exécution via le canal nommé Windows \\.\pipe\LOCAL\ploto-mcp-<identifiant de 64 caractères>. L'identifiant est une valeur fixe dérivée du chemin du profil utilisateur et de l'identifiant de l'application. Le canal limite l'accès à son créateur (le même utilisateur Windows), refuse les clients distants et est créé en mode exclusif afin qu'aucun autre processus ne puisse s'approprier le même nom au préalable. Aucun jeton n'est utilisé. Jusqu'à 16 connexions simultanées sont autorisées, et chaque requête est limitée à 64 Kio.
  • API du terminal (voie de secours) : pour les clients d'IA qui ne lisent pas les paramètres MCP, ploto.ps1, ploto.cmd et ploto.sh envoient des requêtes HTTP depuis le terminal intégré. L'application n'écoute que sur un port dynamique de 127.0.0.1 et n'est pas exposée sur les interfaces externes. Chaque requête exige un jeton Bearer aléatoire de 256 bits, conservé uniquement en mémoire et transmis seulement par les variables d'environnement du terminal intégré (il n'est jamais écrit dans un fichier). L'en-tête Host est vérifié, et les requêtes provenant de navigateurs (avec Origin ou intersites) sont refusées. Le corps des requêtes est limité à 64 Kio. Le jeton est révoqué lors du changement ou de la fermeture du projet, ou à la fermeture de l'application.
  • Contrôles communs : les deux voies passent par le même traitement interne de Ploto ; la vérification du consentement, le démarrage en lecture seule, l'autorisation de modification, l'impossibilité d'enregistrer et le décompte de l'essai s'appliquent donc de la même manière. Les opérations sont traitées une à une, avec un délai de réponse de 30 secondes maximum. Aucune API n'exécute de SQL arbitraire, d'opérations sur les fichiers ou de commandes shell.
  • Moment de l'écoute : les deux voies commencent à écouter au démarrage de la fenêtre de Ploto, mais les opérations sur le projet sont refusées tant que l'utilisateur n'a pas donné son consentement. Lorsque Ploto n'est pas lancé, le processus relais MCP démarré par le client d'IA reste actif, répond aux requêtes en indiquant que Ploto n'est pas lancé et se reconnecte au redémarrage de Ploto. MCP ne peut ni lancer Ploto, ni ouvrir de fichiers, ni modifier les autorisations.
  • Pare-feu Windows : les connexions entrantes se limitent à la boucle locale et au canal nommé ; aucune règle de pare-feu entrante n'est donc nécessaire. Les communications sortantes de la CLI d'IA vers le service d'IA relèvent des spécifications de la CLI d'IA.

Flux de données : le contenu de projet lu par l'IA (noms des tâches, noms des responsables, calendriers, notes, ToDo, étiquettes, etc.) est envoyé par la CLI d'IA au fournisseur du service d'IA choisi par l'utilisateur. Cette transmission ne passe pas par les serveurs du fournisseur de Ploto. Le traitement, notamment l'utilisation pour l'entraînement, la durée de conservation et la région de traitement, est régi par le contrat entre l'utilisateur et le fournisseur du service d'IA. Si des données professionnelles sont traitées, informez les utilisateurs qu'ils doivent utiliser des services et offres d'IA approuvés par l'organisation.

Autorisations et périmètre des opérations :

  • Le consentement est demandé lors du premier affichage du terminal, et les opérations sur le projet sont refusées tant qu'il n'est pas accordé. Le consentement est enregistré sur l'appareil et n'est plus redemandé.
  • Les opérations de l'IA commencent toujours en lecture seule. La modification n'est possible que si l'utilisateur active l'interrupteur ou approuve une demande d'autorisation de modification émise par l'IA. L'autorisation est révoquée au changement ou à la fermeture du fichier.
  • Les modifications de l'IA ne s'appliquent qu'aux données de travail à l'écran ; l'IA ne peut pas enregistrer le fichier .ploto. L'enregistrement est effectué par l'utilisateur dans l'application. Les modifications peuvent être annulées avec la fonction Annuler habituelle de Ploto.
  • L'API de Ploto n'accepte ni SQL arbitraire ni exécution shell. Toutefois, le terminal intégré est un shell doté des droits de l'utilisateur, et les autorisations ci-dessus ne limitent pas les opérations sur les fichiers ni les commandes que la CLI d'IA exécute dans le shell. Celles-ci relèvent des paramètres d'autorisation de la CLI d'IA et des approbations de l'utilisateur.
  • L'historique des opérations n'affiche à l'écran que les noms de méthodes et leur réussite ou échec, pour 30 entrées au maximum, et n'est pas enregistré dans un fichier. Ploto n'enregistre ni ne transmet les conversations, la sortie du terminal ou le contenu des opérations.

Écriture dans les paramètres des clients d'IA : en dehors du dossier de travail (section 5), Ploto écrit ses paramètres de connexion MCP et un court guide de connexion (Skill) dans les paramètres utilisateur des clients d'IA uniquement dans les cas suivants. Seules les entrées de Ploto sont écrites ; les autres paramètres ne sont pas modifiés.

  • Codex : comme Codex ne lit pas de paramètres au niveau du projet, Ploto s'enregistre automatiquement dans %USERPROFILE%\.codex\config.toml (ou sous CODEX_HOME s'il est défini) et dans %USERPROFILE%\.agents\skills à chaque activation de l'intégration IA.
  • Autres (Claude Code, Cursor, Gemini CLI, Antigravity, OpenCode, VS Code / Copilot) : écriture uniquement lorsque l'utilisateur clique sur le bouton d'enregistrement dans l'écran des paramètres de connexion. Rien n'est écrit pour les clients dont le dossier de paramètres n'existe pas, et le fichier ~/.claude.json de Claude Code n'est mis à jour que s'il existe déjà.
  • Les chemins de destination sont affichés à l'écran, et les enregistrements peuvent être supprimés depuis ce même écran.

Instructions transmises à l'IA : Ploto transmet à l'IA des instructions pour piloter correctement l'application (procédures, spécifications de l'API, vérifications avant écriture, interdiction de modifier par supposition, interdiction de rechercher des identifiants ou la base de données, etc.) via la réponse d'initialisation MCP et sous forme de fichiers texte dans le dossier de travail. Ces instructions orientent le comportement de l'IA ; la limite de sécurité est assurée par les mécanismes d'autorisation, de lecture seule et d'impossibilité d'enregistrer décrits ci-dessus. Le texte intégral peut être consulté et copié sur la page distincte « Instructions que Ploto transmet à l'IA ».

Essai et licence : l'essai accepte au total jusqu'à 60 opérations API/MCP. Le compteur et la licence sont gérés sur l'appareil, et l'utilisation n'est pas transmise au fournisseur de Ploto. Les achats de la version Store sont vérifiés par le Microsoft Store.

Désactivation dans une organisation : définir la variable d'environnement système ou utilisateur PLOTO_DISABLE_AUTOMATION=1 amène l'application à refuser l'activation de l'intégration IA. Il s'agit d'un paramètre interne à l'application, qui ne remplace ni le contrôle des applications ni les règles d'usage de l'IA de l'organisation. Gérez l'autorisation des CLI d'IA elles-mêmes par la gestion des postes et les contrôles réseau de l'organisation.

8. Services externes et informations transmises

Microsoft : assure la distribution, les mises à jour, les achats dans le Store, les avis et le diagnostic du système. Le fournisseur de Ploto peut consulter dans Partner Center des informations agrégées de distribution et de qualité.

Stripe : lorsqu'un utilisateur engage un achat en ligne, Stripe traite les informations de paiement, l'adresse e-mail de l'acheteur, le produit, le montant, la devise et la date, les informations de connexion, ainsi que l'empreinte de poste décrite à la section 3.2 de la politique de confidentialité. Les numéros de carte et données analogues sont traités directement par Stripe.

Vercel : reçoit de Stripe les informations de finalisation d'achat et génère une clé de licence signée. Aucune base de données propre aux acheteurs n'est tenue, mais des journaux d'exploitation peuvent être traités.

Resend : envoie la clé de licence à l'adresse e-mail de l'acheteur, en traitant le destinataire, le contenu du message et les informations de distribution.

Google : traite les réponses lorsqu'un utilisateur envoie un formulaire facultatif. Le site officiel utilise Google Analytics 4 et Google Fonts. Google Analytics n'est pas intégré à l'application elle-même.

GitHub : diffuse via GitHub Pages le site officiel, le manuel et le présent document, et peut traiter des informations d'accès standard.

FormSubmit : transmet par e-mail au fournisseur de Ploto les messages envoyés au moyen du formulaire de contact du site officiel.

Service d'IA choisi par l'utilisateur : lorsque le terminal IA est utilisé, la CLI d'IA envoie le contenu du projet à ce service d'IA (section 7). Cela repose sur le contrat entre l'utilisateur et ce prestataire, qui n'est pas un sous-traitant du fournisseur de Ploto.

9. Chiffrement, authentification et mesures de sécurité

Les fichiers .ploto, les copies de travail et les fichiers de verrouillage ne font l'objet d'aucun chiffrement au repos propre à Ploto. Si vous traitez des informations confidentielles, mettez en place la protection de votre côté : fonctions du système telles que BitLocker ou EFS, ACL sur l'emplacement de stockage, droits de partage, sauvegardes et contrôle des sorties de données.

Les licences Pro sont vérifiées sur le poste au moyen d'une signature électronique Ed25519. Ce mécanisme confirme l'authenticité de la clé de licence ; il ne chiffre pas les projets. Les informations de paiement pour les achats en ligne sont saisies sur des pages hébergées par Stripe, et le webhook d'émission de licence vérifie la signature de Stripe avant tout traitement. Les clés privées et les clés d'API des services externes ne sont pas incluses dans l'application.

Votre organisation doit mettre en œuvre des comptes Windows à privilèges minimaux, le chiffrement des postes, le contrôle d'accès aux emplacements de stockage, des sauvegardes, une protection contre les logiciels malveillants, les mises à jour du système et des applications du Store, ainsi que des restrictions sur la saisie d'informations confidentielles dans des formulaires externes.

10. Désinstallation et données résiduelles

La désinstallation de la version Microsoft Store supprime normalement l'espace de données local de l'application géré par Windows. En revanche, les projets, modèles, sources d'import et fichiers exportés situés aux emplacements choisis par l'utilisateur, ainsi que %USERPROFILE%\.ploto (y compris les dossiers de travail IA ai et ai-wsl), ne sont pas supprimés. Pour une suppression complète, l'utilisateur ou l'administrateur du poste doit les supprimer après avoir vérifié l'existence des sauvegardes nécessaires.

Les paramètres MCP et le Skill de Ploto enregistrés dans les paramètres utilisateur des clients d'IA pour l'intégration IA ne sont pas non plus supprimés lors de la désinstallation. Avant de désinstaller, retirez-les depuis l'écran des paramètres de connexion de Ploto, ou supprimez le bloc allant de # >>> ploto MCP >>> à # <<< ploto MCP <<< dans config.toml, les entrées ploto des paramètres JSON et ploto-control dans chaque dossier skills.

Une copie de travail ou un fichier de verrouillage peut subsister après un arrêt anormal ou un problème de droits. Ne supprimez un fichier de verrouillage qu'après vous être assuré que personne n'est en train de modifier le projet concerné.
